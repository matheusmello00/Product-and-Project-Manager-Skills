# Research brief template

Use this skeleton for the saved file `interview-brief-[topic].md`. Keep it under two printed pages.

```markdown
# Interview brief — <topic>  ·  <date>

## Research goal
Understand/Discover <one testable question>.

## Who to talk to (screener note)
- Segment: <role / context>
- Must have: <recent behaviour, e.g. did X in the last 3 months>
- Exclude: <colleagues, people building the product>
- Suggested sample: 5–8 per segment

## Hypotheses to test
| # | Hypothesis | True if we hear… | False if we hear… |
|---|---|---|---|
| 1 | <claim about current behaviour/pain> (source or "assumption") | <observable> | <observable> |
| 2 | … | … | … |
| 3 | … | … | … |

## Interview guide (30 min)
**Warm-up (5 min)** — build rapport, understand context
1. <question>
2. <question>

**Core exploration (20 min)** — dig into the problem
3. <question about the last concrete episode>
   ↳ Tell me more about that · What happened next? · <specific probe>
4. <question>
   ↳ <follow-up> · <follow-up>

**Wrap-up (5 min)** — capture what was missed, referrals
N. "Is there anything I should have asked but didn't?"

## Things to watch for
- <behavioural signal, workaround, hesitation>

## Anti-patterns to avoid
- <topic-specific interviewer mistake>

## Consent and recording
Explain the purpose in one sentence; ask permission to record; confirm confidentiality; the participant may skip or stop at any time.

## Notes
- Assumptions made: <…>
- Context used: <files / none>
- Weak or untestable hypotheses and the suggested replacement: <…>
```

Checks before delivering: ≤ 12 questions; no "Would you…" / "Do you think…"; no question about the PM's solution; ≥ 2 follow-ups per core question; goal starts with Understand or Discover; consent note present.
